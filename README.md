# Arti Clinic — лендинг (React + TypeScript + SCSS Modules)

Современный минималистичный лендинг для медицинского центра **Arti Clinic**.
Цвета — серо-бежевые с мягким голубым акцентом. Плавные анимации при прокрутке без сторонних библиотек (IntersectionObserver).

## Быстрый старт

```bash
npm i
npm run dev
# откройте http://localhost:5173
```

## Структура

- Hero → Benefits → Services → Reviews → Blog → Contact (карта + форма) → Footer

Как публиковать новую статью

Клади Markdown сюда:
content/posts/<slug>.md (как в примере).

Картинки — сюда:
public/blog/<slug>/cover.jpg (и любые другие, если нужны).

В терминале:

npm run build:content # обновит posts.json, rss-dzen.xml, sitemap.xml и post.md

Задеплой статику (см. ниже Yandex Object Storage).

После выката:

# один раз придумай INDEXNOW_KEY и положи его в секреты CI

npm run indexnow

На главной появится карточка, в /blog — список, в /blog/slug — статья.
Дзен сам подтянет статью из /rss-dzen.xml после модерации.

## Сборка и индексирование

`npm run build` собирает статьи, приложение и готовый HTML для главной,
страниц услуг, цен, списка статей и документов. В конце автоматически
проверяются заголовки, canonical, sitemap и структурированные данные,
существование изображений и внутренних ссылок во всех статьях и страницах.

Для генерации HTML нужен браузер: в Windows используется установленный Edge,
в Linux установите Chromium командой `npx playwright install --with-deps chromium`.
Повторная проверка готовой сборки: `npm run check:seo`.
Проверка извлечения описаний статей: `npm test`.

Услуги могут задавать отдельные `seoTitle` и `seoDescription` в
`src/data/services.ts`. Ссылки из статей на три основных направления
определяются по явно указанной теме в `src/data/seoTopics.ts`.
Фотография клиники и логотип для метаданных находятся в `public/images`.
При изменении шаблона статей обновляйте версию кеша в `scripts/build-content.ts`.

Единственный исходник robots.txt — `public/robots.txt`.
Данные маршрутов сборки находятся в `.cache/routes.json`.
`scripts/publish-routes.ts` публикует HTML с `Content-Type: text/html` по точным
ключам Object Storage (`services`, `services/`, `services/index.html` и т. д.).
Это необходимо: подстановка index.html как страницы ошибки оставляет код 404.
Корневая синхронизация больше не использует `--delete`, чтобы не удалять эти ключи.
Ненужные старые файлы в корне при необходимости удаляются отдельно после проверки.

CI сначала публикует контент, затем приложение и маршруты. Он проверяет HTTP 200
для существующих страниц и HTTP 404 для неизвестного адреса. Настройка страницы
ошибки хостинга может быть изменена с index.html на созданный `404.html`;
эта настройка облака сама по себе из GitHub не меняется.

IndexNow: сначала `npm run indexnow -- --prepare-key`, затем публикация файла
ключа, затем `npm run indexnow`. Скрипт проверяет публичную доступность ключа
и отправляет адреса из sitemap, включая услуги. Для локальной проверки без
обращения к поисковикам: `npm run indexnow -- --dry-run`.

Сертификат и перенаправление `www.articlinic.ru` управляются в Yandex Cloud/CDN.
Нужен действующий сертификат на www, затем 301 на https://articlinic.ru
с сохранением пути и параметров. Изменение robots.txt не исправляет TLS.
