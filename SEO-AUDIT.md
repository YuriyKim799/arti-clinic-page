# SEO-аудит articlinic.ru

Дата: 13 сентября 2026 года. Проверена локальная версия проекта.

## Вывод

Есть полезная основа: отдельные страницы услуг, HTML-генерация статей, sitemap, canonical, структурированные данные, контакты и сведения о лицензии. Основные направления улучшений: HTML коммерческих страниц, согласованность URL, медицинская экспертиза контента, переходы из статей к услугам и скорость загрузки.

Первые места нельзя гарантировать изменениями кода. Для оценки потенциала нужны запросы, регион, конкуренты и данные поисковых кабинетов. Это технический и структурный аудит, а не замер текущих позиций или медицинская экспертиза текстов.

## Объём и проверка

- Проверены маршрутизация, входной HTML, SEO-компонент, шаблоны главной, услуг, блога, прайса и ошибок, данные врачей, генератор контента, robots, sitemap, workflow публикации и критические ассеты.
- Автоматически обследованы все 180 Markdown-файлов и HTML 179 опубликованных статей; отдельные тексты прочитаны вручную. Не проводилась построчная медицинская проверка всех статей.
- В sitemap 192 URL: 179 статей, 9 услуг и 4 страницы. У всех опубликованных статей есть HTML и ровно один H1 в статической версии.
- Production-сборка успешно выполнена: `npm.cmd run build -- --outDir .cache/seo-audit-build`.
- Результаты подсчётов: `.cache/seo-scan-results.json`; воспроизведение: `node .cache/seo-scan.cjs`.
- Веб-инструмент получил главную опубликованного сайта без основного текстового содержимого. Для остальных проверенных адресов инструмент вернул ошибки доступа/получения. Это не доказательство недоступности сайта для поисковиков.
- HTTP-статусы, CDN-редиректы, реальный отрендеренный DOM, Lighthouse и полевые Core Web Vitals не проверены. Доступа к Вебмастеру, Search Console и Метрике не было.
- Код приложения не изменялся; добавлены отчёт и вспомогательные файлы в `.cache`.

## Высокий приоритет

### 1. Главная и услуги зависят от JavaScript

`index.html` содержит пустой `#root`; `src/main.tsx` использует `createRoot`; `vite.config.ts` не настраивает SSR/SSG. Для коммерческих маршрутов отдельный HTML не генерируется. Заголовки и содержимое появляются после запуска React.

Google умеет обрабатывать JavaScript, поэтому это не означает автоматического запрета индексации. Но статический HTML уменьшает зависимость от рендеринга и делает контент доступнее роботам.

Решение: генерировать HTML главной, `/services`, девяти услуг, `/price-list` и `/blog` при сборке. Сохранить интерактивность React через подходящую гидратацию. Переезд на другой фреймворк не является обязательным условием. Проверять исходный HTML и соответствие видимой страницы после загрузки JS.

### 2. Canonical статей противоречит сам себе

`scripts/build-content.ts:293` и HTML-шаблон используют `/blog/slug/`. `src/components/SeoAuto.tsx` в `normalizePathname` удаляет завершающий слэш, в том числе из переданного `canonical`. В `BlogPost.tsx` JSON-LD при этом получает исходный адрес со слэшем.

При прямом открытии статической статьи и переходе через React получаются разные сигналы. Выбрать `/blog/slug/` для статей и согласовать canonical, JSON-LD, ссылки и sitemap. На хостинге проверить редиректы вариантов без слэша и `/index.html`; не создавать цепочки редиректов.

### 3. Статическая статья не имеет полноценной оболочки клиники

В `scripts/build-content.ts:478` после CSS выводятся только `main`, `article` и тело материала. Нет общего меню, блока врача, контактов, футера, встроенного блока записи или кода Метрики. На прямом переходе из поиска посетитель получает именно этот шаблон, если хостинг отдаёт сгенерированный файл.

В 0 из 180 исходных текстов обнаружены пути `/services/`. Это конкретно отсутствие ссылок на услуги, а не отсутствие любых ссылок.

Решение: единый шаблон статьи с навигацией, автором/проверяющим врачом, релевантными услугами, контактами и записью. Добавить содержательные ссылки из статей на подходящие услуги и обратно. Согласовать HTML и React-версии.

### 4. Недостаточно явной медицинской ответственности за материалы

В 180 из 180 исходников нет полей `author` и `updated`. Генератор и React используют организацию в качестве автора. Это допустимо технически, но не показывает, какой врач написал или проверил конкретный медицинский текст. Шаблон не выводит блок медицинского рецензента и его квалификацию.

Решение: фактическая проверка материалов врачом, автор/рецензент со ссылкой на профиль, реальная дата проверки и источники для медицинских утверждений. Не назначать врача автором задним числом без подтверждения и не обновлять даты автоматически ради свежести.

В контенте есть множество близких тем о грыжах, болях после дачи и осанке. Возможное пересечение запросов требует анализа показов и содержания; сами похожие заголовки не доказывают каннибализацию. Не удалять материалы массово. Объединять только обоснованные дубли с корректными перенаправлениями.

### 5. Неверная подробная информация второго врача

`src/data/doctors.tsx` назначает Ким Алине Александровне `moreInfo: chiefDoctorMoreInfo`. `src/data/chiefDoctorMoreInfo.tsx` начинается с имени и биографии Тян Виктории Николаевны. `src/pages/ChiefDoctorSection.tsx:807` выводит это содержимое в модальном окне выбранного врача.

Решение: отдельная проверенная биография для каждого врача. Создать самостоятельные URL профилей: сейчас маршрутов врачей нет, а часть сведений доступна только после переключения/открытия модального окна.

### 6. Очень тяжёлые SVG в интерфейсе

- `src/components/LogoIcon/LogoIcon.tsx` импортирует `imagename.svg`: 2 784 082 байта, около 2,09 МБ gzip по сборке.
- `index.html` подключает favicon `arti-logo-tight.svg`: 2 692 727 байт, около 2,03 МБ gzip.
- Hero-видео: WebM 1,47 МБ, MP4 1,21 МБ. Это альтернативные форматы, их размеры нельзя автоматически складывать как обязательную загрузку браузера.

Решение: компактный вектор логотипа и отдельные маленькие favicon. Затем проверить загрузку первого экрана на мобильном интернете. Наличие крупных видео в сборке само по себе не доказывает, что все они скачиваются при открытии.

`src/lib/boot.ts` дополнительно загружает все размеры hero-картинок сразу в AVIF и WebP, вместо выбора подходящего варианта браузером. Этот boot вызывается на всех React-маршрутах. Убрать избыточную загрузку и глобальную загрузку списка статей там, где она не нужна.

## Средний приоритет

### 7. Вся главная находится в одном Suspense

`src/components/Home/Home.tsx` объединяет Hero и нижние секции под `Suspense fallback={null}`. Все lazy-компоненты участвуют в первоначальном рендере; lazy здесь не означает загрузку только при прокрутке. Медленная секция может задержать появление всей этой области.

Первый экран сделать доступным сразу, нижние секции разделить подходящими границами загрузки. `global.scss` скрывает `.reveal` до IntersectionObserver: при добавлении SSG предусмотреть видимый HTML без JS.

### 8. Несуществующие в репозитории изображения метаданных

Не найдены `public/og-default.jpg`, `public/logo-512x512.png`, `public/og/blog-1200x630.jpg`, `public/og/price-1200x630.jpg`, `public/og-services/index-1200x630.jpg`. Страницы услуг также формируют адреса `/og-services/<slug>.jpg`, каталога в public нет.

Это подтверждённое отсутствие локальных файлов, а не подтверждённые HTTP 404 на production: на сервере могут оставаться отдельно загруженные объекты. Добавить реальные файлы либо ссылаться на существующие; проверять HTTP-ответ и MIME-тип. OG нужен прежде всего для превью ссылок, а не как самостоятельный способ повышения позиции.

### 9. Часы работы расходятся

`Home.tsx`: `Mo-Su 09:00-20:00`. `Contact.tsx`: Пн–Сб 09:00–20:00, Вс 10:00–18:00. Вынести сведения о клинике в общий источник, согласовать с фактическим расписанием и карточками в картах.

### 10. Страницы услуг слабо соединены с ценами и врачами

Есть 9 услуг, описания, показания, противопоказания и FAQ — это хорошая основа. Но `ServiceDetail.tsx` не выводит цену услуги, профиль выполняющего её врача, релевантные статьи или путь к конкретной позиции прайса. Поле `priceFrom` в типе данных не используется шаблоном.

Добавить подтверждённую стоимость, специалиста, ход приёма/процедуры и ссылки на связанные материалы. Для консультации невролога оценить отдельную посадочную страницу. Существующую программу лечения грыжи развивать, не создавать конкурирующий дубль без анализа запросов.

### 11. Заголовки и структура текстов

Главный title содержит «Центр лечение» и длинное перечисление методов. Title списка услуг также перегружен. Пример главного title для обсуждения: «Лечение боли в спине и грыжи в Москве — Арти Клиник». Окончательный вариант выбрать по приоритету запросов; фиксированная длина title не является гарантией ранжирования.

Во всех 180 Markdown-файлах отсутствуют заголовки `##`; в просмотренных материалах подразделы оформлены жирными абзацами. Это не автоматический штраф. При редактуре оформить реальные разделы через H2/H3, добавить понятное оглавление там, где оно полезно.

В 178 исходниках description содержит признаки импортного служебного текста. ВАЖНО: текущий генератор использует `excerpt` или выдержку из тела, а не `description`; в 179 итоговых excerpt таких признаков не обнаружено. Чистить исходные данные полезно, но утверждать, что все опубликованные description испорчены, нельзя.

### 12. Статья получает дополнительный H1 при переходе через React

`BlogPost.tsx` извлекает всё содержимое статического `article`, включая H1, и вставляет его ниже собственного H1. Статические статьи имеют по одному H1, но React-ветка добавляет второй. Устранить дублирование заголовка в шаблонах. Несколько H1 сами по себе не означают санкцию, здесь это прежде всего повтор контента и несогласованность представления.

### 13. Невалидные вложенные абзацы услуг

`ServiceDetail.tsx` помещает результат `formatText()`, возвращающий `<p>`, внутрь других `<p>`. Заменить внешние обёртки на `div`, в FAQ также убрать вложенный абзац. Особенно важно до генерации HTML: браузер исправляет такую структуру, что может нарушать гидратацию.

### 14. Несуществующий поиск в JSON-LD

Главная объявляет `SearchAction` с `/search?q=...`, но в `App.tsx` такого маршрута нет. Удалить объявление либо реализовать настоящий поиск, если он нужен посетителям. Не ожидать роста позиций от одной этой правки.

### 15. Измерение SEO-заявок неполное в коде

Метрика инициализирована в `index.html`. В `src` не найдены явные вызовы `ym(..., 'hit', ...)` при переходах React и `reachGoal` при успешной записи. В статическом шаблоне блога счётчика нет.

Проверить настройки кабинета: автоцели могут уже существовать. Затем обеспечить учёт маршрутов и подтверждённой отправки формы, кликов по телефону и мессенджерам. Без этого трудно сравнивать статьи, которые дают чтение, и страницы, которые дают обращения.

## Сборка, публикация и проверки сервера

- `package.json`: обычный `build` запускает только Vite. Генерация контента — отдельная команда.
- `.github/workflows/ci.yml`: sitemap строится в content-job, но изменения `src/data/services.ts` запускают app-job. Добавленная услуга может не попасть в новый sitemap до отдельного запуска сборки контента. Текущий sitemap уже содержит все 9 услуг.
- App и content job могут публиковать корневые sitemap/posts/rss одновременно из разных состояний. Определить единственного владельца этих файлов и порядок публикации.
- `postHash()` учитывает файлы каталога статьи, включая генерируемые результаты, но не версию шаблона. Изменение шаблона не гарантирует пересборку всех существующих HTML. Хешировать исходные данные и версию генератора, исключить выходные файлы из входного хеша.
- Два robots: корневой и `public/robots.txt` отличаются; CI копирует корневой поверх результата. Оставить единый источник и проверять именно опубликованный файл. Текущие правила не запрещают весь сайт.
- React-страница 404 с noindex существует, но она не устанавливает серверный HTTP-статус. Проверить случайный URL, неизвестную услугу и статью: нужны корректные 404/410, а не ответ 200 с ошибкой на экране.
- Проверить HTTP → HTTPS, www → выбранный хост, варианты слэшей, `/index.html`, доступность JS/CSS, Content-Type и сжатие. По локальному коду настройки CDN установить нельзя.

## Порядок работ

1. Зафиксировать базовые данные Вебмастера, Search Console и Метрики: индексируемые URL, запросы, посадочные страницы, клики и обращения. Проверить серверные статусы и мобильные показатели загрузки.
2. Исправить биографию врача, часы, canonical, отсутствующие ассеты метаданных, SVG, лишние preload и вложенные абзацы.
3. Добавить HTML-генерацию коммерческих страниц и общий шаблон блога. Согласовать сборку, sitemap и публикацию. Проверять и прямое открытие URL, и переходы через React.
4. Усилить страницы приоритетных услуг ценами, врачами, ответами на вопросы и релевантными материалами. Создать полноценные профили врачей.
5. Переработать статьи по реальным поисковым запросам, с врачебной проверкой, источниками и переходами к услугам. Начать с материалов, имеющих показы и потенциал обращений.
6. Согласовать сведения в Яндекс Бизнесе и Google Business Profile, актуализировать фото, услуги и реальные отзывы. Измерять результаты по группам запросов и заявкам, учитывая сезонность и изменения сайта.
