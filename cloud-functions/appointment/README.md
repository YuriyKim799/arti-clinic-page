# Онлайн-запись через Mail.ru

Функция `d4ehvps5uj8pkr10vkjs` принимает прежний JSON формы и отправляет письмо
через `smtp.mail.ru:465` с TLS. Получатель по умолчанию: `kimskiy@mail.ru`.
Обработчик подготовлен локально; загрузка в Yandex Cloud и реальная отправка
требуют настройки учётной записи Mail.ru.

## 1. Пароль приложения Mail.ru

Войдите в ящик отправителя `kimskiy@mail.ru`. Откройте Настройки → Все настройки →
Безопасность → Пароли для внешних приложений. Создайте пароль с названием
«Арти Клиник — заявки» и правом **Только отправка писем в Почте**.
Этот пароль используется вместо обычного пароля ящика. Введите его непосредственно
в переменную `SMTP_PASSWORD` облачной функции; не вставляйте в код или чат.

Инструкция: https://help.mail.ru/mail/login/mailer/

## 2. Загрузка в Yandex Cloud

Загрузите подготовленный `.cache/appointment-function.zip` в редактор функции.
В корне ZIP должны быть **четыре отдельных файла**:

- `index.js` — обработчик;
- `send-mail.js` — отправка почты;
- `package.json` — зависимость Nodemailer;
- `package-lock.json` — зафиксированная версия зависимости.

Не копируйте содержимое нескольких файлов в один `index.js`.
Тесты, README и названия путей не являются кодом обработчика.
Yandex Cloud установит зависимость при сборке новой версии.

Параметры версии:

- среда: **Node.js 22**;
- точка входа: **index.handler**;
- таймаут функции: **30 секунд**, не 3 секунды;
- сохранить публичный HTTP-доступ к функции.

Переменные окружения:

| Имя | Значение |
| --- | --- |
| `SMTP_USER` | `kimskiy@mail.ru` |
| `SMTP_PASSWORD` | пароль приложения Mail.ru |
| `MAIL_TO` | `kimskiy@mail.ru` |
| `ALLOWED_ORIGINS` | `https://articlinic.ru,http://127.0.0.1:5173,http://localhost:5173` |

`SMTP_USER` одновременно задаёт отправителя и SMTP-логин. Если нужен другой
отправитель Mail.ru, укажите его полный адрес и его пароль приложения.
Старые переменные Telegram почтовому обработчику не нужны.

Сохраните новую версию, после чего проверьте форму на сайте. Успешный ответ
означает, что SMTP-сервер принял письмо; появление во «Входящих» проверяется
в самом ящике (при необходимости также проверьте «Спам»).

## Диагностика

Общий срок отправки — 20 секунд: при превышении соединение закрывается.
Есть отдельные лимиты подключения, приветствия и ожидания данных.
Автоматических повторов нет, чтобы не создавать дубликаты при потере ответа.

- `mail_send_completed`: почтовый сервер принял письмо для получателя.
- `mail_rejected`: получатель не подтверждён сервером.
- `mail_timeout`: истёк срок отправки. Проверьте исходящий доступ функции к
  `smtp.mail.ru:465`, а при подключении VPC — сетевые настройки/NAT.
- `mail_send_failed`, код `EAUTH`: проверьте SMTP-логин, пароль приложения
  и разрешение отправки через SMTP в Mail.ru.
- `mail_send_failed`, код `ESOCKET`, `ECONNECTION` или `EDNS`: проблема соединения.
- `appointment_config_missing`: отсутствуют настройки или некорректен адрес.

Логи не содержат пароль, содержимое письма или персональные данные заявки.
