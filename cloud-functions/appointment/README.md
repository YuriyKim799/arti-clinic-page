# Онлайн-запись через Mail.ru

Функция `d4ehvps5uj8pkr10vkjs` принимает прежний JSON формы и отправляет письмо
через `smtp.mail.ru:465` с TLS. Получатели: `kimskiy@mail.ru` и `yurakakim777@gmail.com`.
Список задаётся переменной `MAIL_TO`; эти два адреса используются также по умолчанию.
Изменения обработчика и переменных окружения вступают в силу после создания
новой версии функции в Yandex Cloud.

## 1. Пароль приложения Mail.ru

Войдите в ящик отправителя `kimskiy@mail.ru`. Откройте Настройки → Все настройки →
Безопасность → Пароли для внешних приложений. Создайте пароль с названием
«Арти Клиник — заявки» и правом **Только отправка писем в Почте**.
Этот пароль используется вместо обычного пароля ящика. Введите его непосредственно
в переменную `SMTP_PASSWORD` облачной функции; не вставляйте в код или чат.

Инструкция: https://help.mail.ru/mail/login/mailer/

## 2. Загрузка в Yandex Cloud

Загрузите подготовленный `.cache/appointment-antispam.zip` в редактор функции.
В корне ZIP должны быть **четыре отдельных файла**:

- `index.js` — обработчик;
- `send-mail.js` — отправка почты;
- `package.json` — зависимость Nodemailer;
- `package-lock.json` — зафиксированная версия зависимости.

Не копируйте содержимое нескольких файлов в один `index.js`.
Тесты, README и названия путей не являются кодом обработчика.
Yandex Cloud установит зависимость при сборке новой версии.

Параметры версии:

- среда: **Node.js 22**;
- точка входа: **index.handler**;
- таймаут функции: **30 секунд**, не 3 секунды;
- сохранить публичный HTTP-доступ к функции.

Переменные окружения:

| Имя | Значение |
| --- | --- |
| `SMTP_USER` | `kimskiy@mail.ru` |
| `SMTP_PASSWORD` | пароль приложения Mail.ru |
| `MAIL_TO` | `kimskiy@mail.ru,yurakakim777@gmail.com` |
| `ALLOWED_ORIGINS` | `https://articlinic.ru,http://127.0.0.1:5173,http://localhost:5173` |

`SMTP_USER` одновременно задаёт отправителя и SMTP-логин. Если нужен другой
отправитель Mail.ru, укажите его полный адрес и его пароль приложения.
Старые переменные Telegram почтовому обработчику не нужны.

`MAIL_TO` поддерживает один адрес или список через запятую / точку с запятой.
Пробелы по краям убираются; повторяющиеся адреса не получают дубликаты.
Получатели определяются только настройками функции, а не данными формы.

## Проверка заявок перед отправкой

Обработчик проверяет размер и структуру JSON, тип заявки, контактные поля и
разрешённый Origin. Имя и телефон должны быть строками. Телефон допускает
`+7`, `7`, `8` с десятью последующими цифрами или десять местных цифр,
а также обычные пробелы, скобки и дефисы. Имя может быть записано на разных языках.
Для онлайн-консультации и сборника требуется корректный email и врач `kim-alina`.
Очная запись допускает прежний JSON без `appointment_type` или значение
`"appointment"`.

Скрытое поле `website` должно быть пустой строкой или отсутствовать.
Заполненная строка возвращает HTTP 204, а значение другого типа — HTTP 400.
Все три формы передают числовой `t0` — время открытия формы в миллисекундах.
Отсутствующий, некорректный или неположительный `t0` возвращает HTTP 400.
Отправка раньше 900 мс после открытия формы, включая время из будущего,
возвращает HTTP 429 с просьбой повторить попытку. Давно открытая форма
продолжает работать, поскольку максимальный возраст `t0` не ограничен.

Эти проверки отсекают часть автоматических запросов. Клиентские поля,
включая `t0` и Origin, могут быть воспроизведены сторонним отправителем.
Общий лимит частоты для разных экземпляров функции требует отдельного
постоянного хранилища и в этой версии отсутствует.

Внешние адреса страниц выводятся в HTML-письме обычным текстом, ссылки на
разрешённые сайты сохраняются. Пароль и содержимое заявки в логи не выводятся.
Настройки отправителя и получателей определяются переменными функции.
После загрузки ZIP создайте новую версию функции, сохранив почтовые настройки,
и проверьте актуальную страницу сайта. Успешный ответ означает, что SMTP-сервер
принял письмо. Его появление во «Входящих» проверяется в почтовом ящике.

## Заявки на онлайн-консультацию

Обычная форма записи продолжает отправлять прежний JSON без обязательного email.
Форма на странице Ким Алины дополнительно передаёт:

```json
{
  "appointment_type": "online-consultation",
  "doctor": "kim-alina",
  "name": "Фамилия Имя Отчество",
  "email": "patient@example.org",
  "phone": "+7 (000) 000-00-00",
  "website": "",
  "t0": 1793952000000
}
```

Остальные поля формы (`page`, `page_text`, `website`, `t0`) сохраняют прежнее назначение.
Для онлайн-консультации email обязателен: сервер проверяет формат, тип и длину
(не более 254 символов), запрещает переводы строк. Поддерживается только
`doctor: "kim-alina"`; имя врача «Ким Алина Александровна» берётся из обработчика,
а не из свободного текста клиента.

У письма об онлайн-консультации отдельная тема, а в HTML и обычном тексте указаны
тип заявки, врач, ФИО, email, телефон и страница. Email пациента помещается только
в содержимое письма: отправитель и получатели остаются настройками клиники.
Письма отправляются на оба адреса из `MAIL_TO`, без отдельного письма пациенту.

Чтобы новые поля появились в уведомлениях, загрузите новый ZIP и создайте новую
версию облачной функции. Одного обновления страницы сайта недостаточно:
ранее развёрнутый обработчик дополнительные поля не выводит.
При обновлении сохраните текущие `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_TO`,
`ALLOWED_ORIGINS` и остальные параметры функции.

## Заявки на сборник упражнений

Кнопка «Купить сборник упражнений» на странице Ким Алины передаёт тот же набор
контактных полей, но с другим типом заявки:

```json
{
  "appointment_type": "exercise-collection",
  "doctor": "kim-alina",
  "name": "Фамилия Имя Отчество",
  "email": "buyer@example.org",
  "phone": "+7 (000) 000-00-00",
  "website": "",
  "t0": 1793952000000
}
```

ФИО, email и телефон обязательны. Проверки email и врача такие же, как для
онлайн-консультации. Получатели остаются `kimskiy@mail.ru` и
`yurakakim777@gmail.com` из `MAIL_TO`; письмо покупателю не отправляется.

Уведомление имеет тему «Заявка на сборник упражнений — Арти Клиник» и тип
«Покупка сборника упражнений». Внутри указаны врач, ФИО, email, телефон и страница.
Обработчик фиксирует заявку: он не принимает и не подтверждает оплату,
не подтверждает покупку и не выдаёт сборник автоматически. Цена и способ
получения не задаются обработчиком и не берутся из произвольных полей клиента.

Для активации загрузите `.cache/appointment-antispam.zip` и создайте
новую версию функции, сохранив текущие переменные окружения и параметры.
Обновление совместимо с обычной записью и заявками на онлайн-консультацию.

## Диагностика

Общий срок отправки — 20 секунд: при превышении соединение закрывается.
Есть отдельные лимиты подключения, приветствия и ожидания данных.
Автоматических повторов нет, чтобы не создавать дубликаты при потере ответа.

- `mail_send_completed`: почтовый сервер принял письмо хотя бы для одного получателя.
- `mail_partial_delivery`: один из получателей не подтверждён сервером; в логе
  указано количество принятых адресов. Если заявка принята хотя бы для одного
  получателя, форма сообщает об успехе, чтобы повторная отправка не создала дубликат.
- `mail_rejected`: ни один из настроенных получателей не подтверждён сервером.
- `mail_timeout`: истёк срок отправки. Проверьте исходящий доступ функции к
  `smtp.mail.ru:465`, а при подключении VPC — сетевые настройки/NAT.
- `mail_send_failed`, код `EAUTH`: проверьте SMTP-логин, пароль приложения
  и разрешение отправки через SMTP в Mail.ru.
- `mail_send_failed`, код `ESOCKET`, `ECONNECTION` или `EDNS`: проблема соединения.
- `appointment_config_missing`: отсутствуют настройки или некорректен адрес.

Логи не содержат пароль, содержимое письма или персональные данные заявки.

## Локальные тесты

Из этого каталога: `npm.cmd ci`, затем `npm.cmd test`.
Тесты подменяют SMTP-соединение и блокируют неожиданные HTTP-запросы.
Проверяются все три типа заявок, формат контактов, скрытое поле,
минимальное время заполнения, подтверждение доставки и обработка ошибок.
Реальные письма при тестировании не отправляются.
